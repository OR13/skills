## Is it one problem?

No — it's two, and you should one-shot the first.

**Problem A (one shot now): the service never defined "once".** Refund and webhook are the same bug wearing different clothes — a duplicate arrives, nothing arbitrates it, the side effect runs twice. `charge()` already solved this and neither path reused it. Settlement belongs here too for a reason nobody has named yet: an unbounded nightly run that overruns into the next night has no lock, so two runs settle the same rows. That's a third duplicate-money path hiding inside what looks like a performance bug.

**Problem B (waiting): the test suite can't catch any of this.** All three tests are sequential; the failures are races. Fixing the tests' *shape* is a suite-wide job, and it's waiting on Problem A to establish what the assertions should say.

## Plan

- **Problem** — This service has no written definition of "once", so refund, webhook, and settlement each invented their own and each got it wrong; done is one ADR defining the rule plus each path enforcing it under a concurrent test.
- **Approach** — Fan out in-session after a serial Phase 0. Separate worktrees lose because refund and webhook consume the same dedupe primitive and the same migration — isolation buys collisions, not speed — and this is four small files, not tens of minutes per worker.
- **Steps** — Phase 0 (me, serial): read four sources, three tests, both ADRs; write `docs/adr/0013-idempotency.md` fixing replay semantics, dedupe key, and transaction boundary; freeze the dedupe helper signature and migration so W1/W2 can't collide. W3 dispatches alongside Phase 0 (independent). Phase 1 parallel: W1 refund, W2 webhook, W3 settlement. Phase 2: critic via the installed `/code-review`, then full suite.
- **Verification** — Every worker demonstrates its new test failing on pre-fix code and passing after, in its return. Gate: `pytest tests/ -x` green **and** the settlement test inside the existing 45s CI timeout without raising it. Critic must name one thing to delete.
- **Operator input** — One decision, below.

**The decision:** ADR-0007 says handlers "MUST be idempotent, keyed on provider event id". `test_webhook_replay_rejected.py` asserts a replay is **rejected**. Those are different semantics. I recommend replay — return the stored result and 200, matching `charge()`. Rejection with a 4xx makes most providers retry on backoff forever, which is plausibly how double-processing survived a passing suite. Taking the recommendation means W2 rewrites and renames that test to assert the opposite of what it asserts today. That's your call, not mine.

**Standing assumption, not blocking:** settlement gets a bounded run that drains *across* nights — batch, cursor, wall-clock ceiling, backlog-depth metric that alerts if the backlog grows run over run. Say so if a nightly must fully drain or page.
