## Plan

**Problem** — Decide which of the four patches are trustworthy and whether they compose, with no spec and no reviewer budget from you.

**Approach** — Fan out in-session, staged in three phases. It beats separate sessions because the phases are *dependent* and nothing is being written, so worktree isolation buys nothing. It beats straight-through because independent reviewers don't anchor on each other's conclusions — which matters most when there's no spec to anchor to.

The structural call: **the harness patch is not peer to the other three.** It rewrites the thing that would verify them. If it changes what `make test` asserts, a green suite on parser+cache+ranking means nothing. So it goes first, alone, and its job is to decide whether the oracle still exists.

The second call: the three file reviewers will each miss the same thing — the **cache key**. If the parser changes query normalization and the cache keys on parsed queries, caching silently changes semantics. If ranking changes scores and the cache stores ranked results, stale entries outlive the ranking change. Nobody scoped to one file sees that, so Phase 3 is scoped to seams, not files.

**Steps** — Phase 0: I read all four patches and record baseline `make test`. Phase 1: harness worker, alone. Phase 2: parser/cache/ranking in parallel. Phase 3: seam worker fed Phase 2's output. Phase 4: I reconcile to land / land-with-fix / drop.

**Verification** — `git apply --check` per patch, then all four together (conflicts are a finding, not an error). Baseline `make test` on unpatched HEAD recorded first; **if baseline is red, I stop and report**, because a red baseline means there is no oracle. Falsifiable assertion: the harness patch must not reduce executed test-case count versus baseline without the Phase 1 worker naming the reason.

## Reviewer briefs

Common to all: **Scope** is read-only — read the assigned patch, the file it touches, and pre-patch HEAD; do not apply, do not edit, do not run `make test` (I own the baseline). **Return** is `## Verdict` (land / land-with-fix / drop) · `## Behavior deltas` (one row per observable change: input → old output → new output) · `## Findings` (severity, location, why) · `## Unknowns`. Empty state is the literal `NO_FINDINGS_DETECTED` — do not pad.

**1 · Harness (Phase 1, blocking)**
> **Hunt for:** assertions deleted or weakened rather than moved; tests that now pass because setup changed rather than because behavior is correct; fixtures that hardcode expectations matching one of the *other three* patches (that's the harness pre-approving its neighbors); suite-level try/except or skip decorators that convert failure into silence; reduced case count.
> **Must hold:** every assertion in the old harness is either present in the new one or explicitly justified. The new harness fails when given deliberately wrong output.
> **Extra return field:** `## Oracle status` — is `make test` still a trustworthy verifier of the other three patches? Yes / no / conditional.

**2 · Parser**
> **Hunt for:** changes to query normalization (case, whitespace, punctuation, unicode) that alter the *identity* of a query without altering its meaning; operator precedence changes; silent acceptance of previously rejected input, or rejection of previously accepted input; any change to the parsed representation's structure or serialization.
> **Must hold:** for every input class, either output is byte-identical to pre-patch or the delta is listed in `## Behavior deltas`.
> **Extra:** flag every field of the parse output that downstream code could key or hash on.

**3 · Cache**
> **Hunt for:** what exactly the cache key is derived from, and whether that derivation is stable across the other patches; missing invalidation on index or config change; caching of *ranked* results rather than raw matches; unbounded growth or absent eviction; cached error/empty states; read-modify-write races.
> **Must hold:** two queries that must return different results can never collide on a key. A cache hit is observationally identical to a miss.
> **Extra:** state the cache key derivation verbatim.

**4 · Ranking**
> **Hunt for:** score-scale changes (bounded → unbounded, or reversed sort) that downstream cutoffs would misread; tie-breaking that became nondeterministic; new per-document work inside the ranking loop; hardcoded weights replacing configured ones; changes to result *count* as well as order.
> **Must hold:** ranking is a pure function of (query, document set) — same inputs, same order, every time.
> **Extra:** is the score comparable across queries, or only within one?

**5 · Seam (Phase 3, fed Phases 1–2)**
> **Scope:** read all four patches plus the prior findings. Review no file in isolation.
> **Hunt for:** cache keys derived from parser output the parser patch changed; cached results computed under the old ranking; harness fixtures encoding one patch's behavior as another's expectation; two patches editing the same lines; ordering assumptions between parse → cache → rank.
> **Must hold:** all four applied together produce the same observable behavior as each applied alone, except where a delta is listed and justified.
