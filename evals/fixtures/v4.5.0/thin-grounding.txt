## The brief

**Scope.** Read `src/issue.ts`, `src/verify.ts`, `src/types.ts`, `README.md`, `package.json`. Fetch <https://www.w3.org/TR/vc-data-model-2.0/> and quote it — do not recall it; your training data contains 1.1 and the differences are the point of this review. Write nothing: no edits, no proposed patches. Fixes are a later shot, and a fix proposed now reads as a fix agreed. Off limits: crypto library choice, build setup, test coverage, style.

**Hunt for** — spec section is where the requirement lives, file is where this repo asserts the contrary:

1. **Claims at top level, not under `credentialSubject`.** `issue()` spreads claims in; `types.ts` has no such field. §4.4 requires it.
2. **`type` optional** — `types.ts:type?: string[]`. §4.3 requires it and requires `VerifiableCredential` among its values.
3. **`issuer` optional and under-typed** — `issuer?: string`. §4.2 requires it and permits an object carrying an `id` URL, which a bare string can't express.
4. **`@context` as `string[]`** — §4.1 requires first value exactly `https://www.w3.org/ns/credentials/v2`, and permits later entries to be maps. Flag any `https://www.w3.org/2018/credentials/v1`.
5. **1.1 carryover names** — `issuanceDate`/`expirationDate` were replaced by `validFrom`/`validUntil`.
6. **`id` not a single absolute URL**, or repeated on a node. §4.5.
7. **Unsecured output presented as verifiable.** `issue()` takes `key` — determine whether it's used for anything. `verify()` returns `true` unconditionally. Under §7, a credential with no Data Integrity proof or JOSE/COSE envelope is a *credential*, not a *verifiable* one — so a type named `VC` with no proof field is itself a claim the library doesn't meet.
8. **README claims the code contradicts.**

The list is a floor; report violations outside it.

**Must hold.** Every finding cites a section number *and* the normative keyword (MUST/SHOULD/MAY) from fetched text, *plus* `file.ts:line` — one without the other isn't yet a finding. Separate MUST violations from SHOULD/MAY gaps; don't inflate. Absent optional features (`credentialStatus`, `credentialSchema`, `evidence`, `refreshService`, `termsOfUse`) are not violations unless emitted malformed. If the source is unreadable, stop and say so rather than reviewing the listing.

**Return.** `## Summary` (≤3 sentences), `## MUST violations` and `## SHOULD / MAY gaps` as tables with columns *Property · Spec § + keyword · Repo location · What it does · What the spec requires*, then `## Uncertain`. Empty section → `NO_FINDINGS_DETECTED`. No padding.

**Order.** Phase 0 operator → Phase 1 parallel → Phase 2 I merge → Phase 3 fixture.

**Deltas.** Reviewer A owns §4–5, hunts 1–6 and 8; its question is *if a verifier ignored all signatures, would this be a well-formed VCDM 2.0 credential?* Reviewer B owns §7–8 and the media-type registrations, hunts 7 plus what `key` is for, whether the library picks enveloping (`application/vc+jwt`, `+sd-jwt`, `+cose`) or embedded or neither; its question is *what makes `issue()` output verifiable by someone who didn't issue it?*
